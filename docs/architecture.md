# Архитектура

Статический сайт на Astro: страницы собираются в HTML заранее, весь текст виден без JavaScript.

## Слои

| Слой | Папка | Правило |
| --- | --- | --- |
| Страницы и шаблоны | `src/pages`, `src/layouts` | Разметка и сборка данных для страницы |
| Домен | `src/domain` | Чистые функции и типы, без DOM и хранилища, покрыты тестами |
| Браузер | `src/client`, `src/lib/storage.ts` | Скрипты страниц и единственная точка работы с `localStorage` |
| Контент | `src/content` | Уроки и памятки в Markdown, схема в `src/content.config.ts` |

Слои дополняются вместе с пунктами плана, которые их вводят.

## Контент

Урок — файл `src/content/lessons/*.md`. Во frontmatter: постоянный `id`, день, цель, вопрос, два чек-листа, задание с полями, ссылка
на памятку, источники. В теле обязательны разделы `## История`, `## Пример из жизни`, `## Суть`, `## Вопрос этики`.

`npm run check:content` запускается в гейте и перед каждой сборкой. Он проверяет обязательные блоки, источники, уникальность id по всему
курсу, ссылки на памятки, родовые формы про читателя и запрещённые слова: вещества, дозы, способы. В разделах с героями и историей род
разрешён, а запрещённые слова проверяются везде. Правила — чистые функции в `src/domain/content-rules.ts`, покрыты тестами.

## Страницы и разметка

- `src/layouts/BaseLayout.astro` — метаданные, Open Graph, JSON-LD, шапка и подвал.
- `src/components/LessonView.astro` — шаблон урока: вопрос, блоки из Markdown, задание, чек-листы, памятка, источники.
- `src/lib/rehype-lesson-blocks.mjs` — оборачивает разделы Markdown в блоки: «История» — фотокарточка, «Пример из жизни» — записка с
  подписью, что герои придуманы.
- `/day/N/` — урок дня или, если у дня есть части, список частей; `/day/N/часть/` — отдельная часть.

## Записи и копия данных

- `src/components/NoteField.astro` — поле задания, общее для урока и `/my-family`. Чувствительное поле получает флажок «Сохранять эту запись» и
  `spellcheck="false"`, чтобы текст не уходил в облачную проверку орфографии браузера.
- `src/client/notes.ts` — сохранение записей и согласие. `src/client/my-family.ts` — экспорт через `Blob`, импорт через `File.text()`,
  «стереть всё» через нативный `<dialog>`. Сеть не участвует, e2e это проверяет.
- `src/domain/notes.ts`, `src/domain/backup.ts` — форматы и проверки недоверенных данных. Описание форматов — `docs/save-format.md`.

## Памятки и печать

- `/memos/` показывает все памятки, `/memos/<id>/` — один лист. Список строится от опубликованных уроков (`src/lib/memos.ts`), поэтому памятка
  дня-черновика не попадёт в публикацию.
- Стили печати — в конце `src/styles/global.css`: A4, белый лист, чёрный текст в любой теме, без шапки. Класс `.no-print` скрывает элемент на бумаге.
- e2e строит PDF каждой памятки и проверяет, что она занимает одну страницу.

## Помощь и безопасность страницы

- `/help/` собирается из `src/data/helplines.ts`. Это единственное место с контактами, у каждого есть источник и дата проверки.
- Тест `tests/unit/helplines.test.ts` проверяет данные через `src/domain/helplines.ts`, в том числе совпадение цифр подписи и `tel:`.
- `heavy` в `BaseLayout` включает прилипающую полосу `SafetyBar`: ссылка на помощь и «Быстрый выход». Кнопка стоит первой в порядке фокуса и уводит
  через `location.replace`, поэтому «назад» не возвращает на страницу. Без JavaScript это обычная ссылка.
- Урок с `heavy: true` получает ещё и предупреждение `HeavyNotice`.

## Черновики

Уроки с `draft: true` видны при разработке и в `npm run build:drafts` (его использует гейт), а обычный `npm run build` их пропускает. Так
день 5 можно проверять, но нельзя случайно опубликовать без проверки специалистом.

## Безопасность

На GitHub Pages нельзя задать заголовки, поэтому Astro кладёт CSP в тег `meta` с хешами скриптов и стилей (`security.csp`). Значит,
встроенные обработчики и атрибут `style` в разметке не работают: скрипты только через Astro. `referrer` отключён.

## Маршруты

`base` равен `/family-100`, адреса заканчиваются косой чертой. Внутренние ссылки строятся от
`import.meta.env.BASE_URL`, поэтому проект с первого дня работает в подпапке, как на GitHub Pages.

## Сборка и проверки

- `astro build` кладёт сайт в `dist/`.
- e2e идут по собранному сайту через `astro preview` с флагом `--ignore-lock`. Без него Astro, заметив запуск
  из-под агента, уводит сервер в фон, и Playwright считает, что сервер упал.

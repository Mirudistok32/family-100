# Архитектура

Статический сайт на Astro: страницы собираются в HTML заранее, весь текст виден без JavaScript.

## Слои

| Слой | Папка | Правило |
| --- | --- | --- |
| Страницы и шаблоны | `src/pages`, `src/layouts` | Разметка и сборка данных для страницы |
| Домен | `src/domain` | Чистые функции и типы, без DOM и хранилища, покрыты тестами |
| Браузер | `src/client`, `src/lib/storage.ts` | Скрипты страниц и единственная точка работы с `localStorage` |
| Контент | `src/content` | Уроки и памятки в Markdown, схема в `src/content.config.ts` |

Слои дополняются вместе с пунктами плана, которые их вводят.

## Контент

Урок — файл `src/content/lessons/*.md`. Во frontmatter: постоянный `id`, день, цель, вопрос, два чек-листа (`self` и `together`), задание с полями, ссылка
на памятку, источники. В теле обязательны разделы `## История`, `## Как было у нас`, `## Пример из жизни`, `## Суть`, `## Советы`, `## Вопрос этики`.

`npm run check:content` запускается в гейте и перед каждой сборкой. Он проверяет обязательные блоки, ленту эпох (от славян до «Сейчас»), советы (не меньше трёх, у каждого указано, откуда он), источники, уникальность id по всему
курсу, ссылки на памятки, родовые формы про читателя, запрещённые слова и темы, которых в курсе нет (`findBannedTopic`). В разделах с героями и историей род
разрешён, а запрещённые слова проверяются везде. Правила — чистые функции в `src/domain/content-rules.ts`, покрыты тестами.

`tests/e2e/quality.spec.ts` проходит все страницы из `dist`, поэтому новая страница попадает в аудит сама: axe в обеих темах, порядок
заголовков, масштаб 200 и 400 %, двойные знаки препинания. Клавиатуру и печать он проверяет на страницах разных типов. Тот же `findBannedTopic` проходит по тексту всех страниц.

## Страницы и разметка

- `src/layouts/BaseLayout.astro` — метаданные, Open Graph, JSON-LD, шапка и подвал.
- `src/components/LessonView.astro` — шаблон урока: вопрос, блоки из Markdown, задание, чек-листы, памятка, источники.
- `src/lib/rehype-lesson-blocks.mjs` — оборачивает разделы Markdown в блоки: «История» — фотокарточка, «Как было у нас» — лента эпох, «Пример из жизни» — записка с
  подписью, что герои придуманы, «Советы» — нумерованный список со сквозными номерами.
- `src/lib/rehype-base-links.mjs` — внутренние ссылки в Markdown пишем от корня (`/memos/`), подпапку публикации добавляет плагин.
- `/day/N/` — урок дня. Частей у дней нет.

## Записи и копия данных

- `src/components/NoteField.astro` — поле задания, общее для урока и `/my-family`. Чувствительное поле получает флажок «Сохранять эту запись» и
  `spellcheck="false"`, чтобы текст не уходил в облачную проверку орфографии браузера.
- `src/client/notes.ts` — сохранение записей и согласие. `src/client/my-family.ts` — экспорт через `Blob`, импорт через `File.text()`,
  «стереть всё» через нативный `<dialog>`. Сеть не участвует, e2e это проверяет.
- `src/domain/notes.ts`, `src/domain/backup.ts` — форматы и проверки недоверенных данных. Описание форматов — `docs/save-format.md`.

## «Аудит капиталов»

- `task.tool: capital-audit`, разметка в `src/components/CapitalAudit.astro`, тексты в `src/data/capital-audit.ts`, подсчёт в `src/domain/capital-audit.ts`, показ в `src/client/capital-audit.ts`.
- Ответы идут через `readToolNote` и `writeToolNote` из `src/client/notes.ts`. Напрямую писать в хранилище нельзя: у `notes.ts` своя копия записей, и следующее сохранение поля затёрло бы аудит.
- Без JavaScript видны все вопросы обеих версий и все шаги, итоги скрыты.

## Семейная конституция

- Форма и лист на `/my-family/#constitution`: разметка в `src/components/Constitution.astro`, тексты в `src/data/constitution.ts`, сборка и оценка длины в `src/domain/constitution.ts`, показ в `src/client/constitution.ts`.
- Части — обычные `NoteField`, поэтому сохранение, согласие, копия и «стереть всё» работают сами. Запись из конституции в списке заданий на этой странице не показываем: одна запись — одно поле.
- Лист строится из полей, а не из хранилища, и только через `textContent`. После импорта, удаления и записи из другой вкладки `notes.ts` шлёт событие `NOTES_RELOADED`, и лист собирается заново.
- На печать со страницы `/my-family` идёт только лист: всё остальное под классом `.no-print`. e2e строит настоящий PDF и проверяет, что на пределе `MAX_DOCUMENT_LINES` выходит не больше двух страниц. За пределом страница предупреждает, но печатать не мешает.
- Без JavaScript видна форма с вопросами обеих версий, а версия, лист и печать скрыты.

## Этика и завершение

- `/ethics/` не хранит свой текст: `src/domain/ethics.ts` разбирает раздел «Вопрос этики» каждого опубликованного урока на вопрос и позиции. Поэтому страница не разойдётся с уроками. Мыслители — поле `thinkers` во frontmatter.
- `check:content` требует от раздела вопрос жирной строкой, минимум две позиции и упоминание каждого мыслителя в тексте.
- `/finish/` открывается с дня 7 кнопкой «Что дальше». `src/domain/finish.ts` считает только сделанное и не показывает нули. Страница ничего не пишет в хранилище.

## Памятки и печать

- `/memos/` показывает все памятки, `/memos/<id>/` — один лист. Список строится от опубликованных уроков (`src/lib/memos.ts`), поэтому памятка
  дня-черновика не попадёт в публикацию.
- Стили печати — в конце `src/styles/global.css`: A4, белый лист, чёрный текст в любой теме, без шапки. Класс `.no-print` скрывает элемент на бумаге.
- e2e строит PDF каждой памятки и проверяет, что она занимает одну страницу.

## Черновики

Уроки с `draft: true` видны при разработке и в `npm run build:drafts` (его использует гейт), а обычный `npm run build` их пропускает. Сейчас черновиков нет.

## Безопасность

На GitHub Pages нельзя задать заголовки, поэтому Astro кладёт CSP в тег `meta` с хешами скриптов и стилей (`security.csp`). Значит,
встроенные обработчики и атрибут `style` в разметке не работают: скрипты только через Astro. `referrer` отключён.

## Маршруты

`base` равен `/family-100`, адреса заканчиваются косой чертой. Внутренние ссылки строятся от
`import.meta.env.BASE_URL`, поэтому проект с первого дня работает в подпапке, как на GitHub Pages.

## Сборка и проверки

- `astro build` кладёт сайт в `dist/`.
- e2e идут по собранному сайту через `astro preview` с флагом `--ignore-lock`. Без него Astro, заметив запуск
  из-под агента, уводит сервер в фон, и Playwright считает, что сервер упал.
